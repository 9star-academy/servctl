# servctl v1 Implementation Plan

**Goal:** Register an uploaded executable as a persistent Linux systemd service with one command, and distribute servctl through a checksum-verified GitHub Release installer.

**Architecture:** A Go standard-library CLI parses arguments; a systemd package validates and renders units and invokes system tools without a shell. systemd owns process supervision and journald owns logs. No daemon, Docker, database, or application-source changes are required.

**Tech Stack:** Go, Bash installer, GitHub Actions, Linux systemd (240+, target Ubuntu 20.04+).

The user approved implementation in this checkout. Execute in this session; do not commit, push, tag, publish releases, or modify a server.

## Accepted contract

- `servctl install NAME --exec PATH --workdir DIR --user USER -- ARG...` writes `/etc/systemd/system/NAME.service`, reloads, enables and starts it. Working directory defaults to the invocation directory. User must be explicit; it must already exist.
- Relative executable paths resolve against the invocation directory. Programs run in the foreground. Ports, application configuration, file uploads, and builds remain the application's responsibility.
- `start`, `stop`, `restart`, `status`, `logs [--follow]`, and `uninstall` accept a service name. Only regular unit files marked as managed by servctl can be managed.
- Reject existing units (including system/vendor/runtime units and masked units), path traversal, malformed names, non-executable programs, missing users and directories.
- Render systemd arguments literally, including whitespace, quotes, backslashes, percent specifiers and dollar signs. No shell execution.
- Verify staged units before atomically creating the destination without overwrite. Roll back a new install on activation failure; retain the unit if rollback cannot safely stop/disable it and report the cleanup failure.
- Check process state after a short observation period; do not claim application/HTTP readiness. Use `Restart=on-failure` with bounded restart rate.
- Installer supports Linux amd64/arm64, requires root, curl, tar and sha256sum, downloads versioned archives and checksums, verifies before replacing only the CLI binary. No remote script is executed by the installer.

## Task 1 — Unit configuration

Files: `go.mod`, `internal/systemd/config.go`, `internal/systemd/config_test.go`.
Write table-driven invalid-name/input and literal-argument tests; run to observe failure; implement validation and rendering; rerun tests.

## Task 2 — Service lifecycle

Files: `internal/systemd/manager.go`, `internal/systemd/manager_test.go`, `internal/systemd/runner.go`.
Use real temporary files and a recording command runner to test no-overwrite, vendor collisions, preflight failure, activation failure/rollback, non-managed service protection and uninstall. Implement ordered lifecycle operations and inspect error propagation.

## Task 3 — CLI

Files: `cmd/servctl/main.go`, `internal/cli/cli.go`, `internal/cli/cli_test.go`.
Test name-first flag parsing, exact arguments after `--`, required flags, unsupported commands/platforms, root requirements and backend error exit codes. Implement Chinese help, version and signals for log following.

## Task 4 — Distribution

Files: `scripts/install.sh`, `scripts/test-install.sh`, `scripts/test-systemd.sh`, `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `.gitignore`, `README.md`.
Test installer with local fake downloads (never real /usr/local/bin writes), including checksum failure and unsupported architecture. Build static Linux amd64 and arm64 archives with version injection and SHA-256 sums. Release workflow runs on version tags, with tests before upload. CI includes actual systemd smoke tests on disposable Ubuntu runners.

## Acceptance

- `go test -race -coverprofile=coverage.out ./...`, `go vet ./...`, formatting and `git diff --check` pass; aim for >=80% meaningful package coverage.
- `bash -n scripts/*.sh` and installer fixture tests pass. Linux amd64 and arm64 cross-build successfully.
- Linux smoke test verifies active/enabled, correct user/cwd/arguments, restart, existing-name refusal, uninstall preserving business files, and failed-start rollback. Reboot verification requires a separate disposable VM/manual step.
- Document that release installation URL is not usable until code is pushed and a GitHub Release containing these assets is published. Local checks are not evidence of release publication or Linux runtime success.
